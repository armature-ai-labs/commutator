# Commutator

**An open-source AI gateway for robots.** Commutator routes every robot request to the right model, on the right compute, inside a safety envelope that no model can override.

A robot doesn't run one model. A pick needs a vision-language-action policy at 30 Hz, "what's on the shelf?" needs a vision-language model, a ten-step chore needs a planner, and "stop!" needs no model at all. Commutator decides which model handles each request, where it runs (onboard, an edge GPU, the cloud or a browser), what it falls back to, and, in later releases, when it may use the GPU and what limits apply to its output before anything reaches the motors.

Built by [Armature AI Labs](https://armatureailabs.com), a physical AI and robotics lab in Bengaluru. Written in Rust.

## Status: 0.0.1, routing only

This first release is the routing core and an HTTP API that **returns routing decisions without calling any model**. It is a faithful Rust port of [solo-router](https://github.com/ddiddi/solo-router):

- It reads solo-router's config format unchanged.
- It makes the same decisions, field by field, on 984 single requests and 144 multi-stage tasks generated by running solo-router itself (`tests/parity/`).

Commutator is **not a safety system** and is not certified for any use. Keep a hardware emergency stop on every robot.

## What it does today

For each request, Commutator:

1. **Reads signals:** intent, short or long horizon, safety (normal, elevated, critical), latency tier from the control rate, network state, battery, embodiment, observations.
2. **Picks a decision:** the first matching rule by priority, such as emergency stop, real-time manipulation or long-horizon planning.
3. **Rejects models that can't serve the request,** with a reason for each: not reachable, no API key, missing runtime, wrong robot, missing camera, too slow for the latency budget (action chunking counted), below the control rate, or below the safety tier.
4. **Ranks the rest** by quality, latency and cost, with penalties on degraded networks and low batteries.
5. **Builds a fallback chain** that always ends in the deterministic `safety-controller`.

A stop command or e-stop flag skips everything and routes to `safety-controller` with a hold-position guardrail.

## Quick start

```bash
git clone https://github.com/armature-ai-labs/commutator
cd commutator
cargo build --release

# Check the built-in config
./target/release/commutator check-config

# Route one request
./target/release/commutator route '{"instruction":"pick up the red cup","embodiment":"so101","observations":["rgb","proprio"],"control_hz":30}'

# Run the API
./target/release/commutator serve --host 127.0.0.1 --port 8899
curl -s localhost:8899/v1/route -H 'content-type: application/json' \
  -d '{"instruction":"stop!","embodiment":"so101"}'
```

Use your own config with `--config path/to/router.yaml` or `COMMUTATOR_CONFIG`.

## HTTP API

| Method and path | What it does |
|---|---|
| `GET /health` | Status, version and model count |
| `GET /v1/models` | Every configured model, plus `commutator/auto` |
| `GET /v1/providers` | Cloud providers and whether a key is configured (from the server environment or `x-<provider>-api-key` headers) |
| `POST /v1/route` | Route one robot request. Response headers `x-commutator-decision`, `-model`, `-location`, `-safety` |
| `POST /v1/task` | Route each pipeline stage (perceive, reason, act) for one task |
| `POST /v1/chat/completions`, `POST /v1/actions` | Return 501 in this release: calling model backends is not implemented yet |

Request fields: `instruction`, `embodiment`, `observations`, `control_hz`, `latency_budget_ms`, `network` (online, degraded, offline), `battery_pct`, `humans_nearby`, `estop`, `preference` (quality, latency, cost, balanced), `locations`, `client_runtimes`, `providers`, `overrides`.

The default model set and its latency numbers come from solo-router and are **illustrative**. Commutator's next step is to replace them with numbers measured on real hardware.

## Roadmap

| Release | Adds |
|---|---|
| 0.1 | `commutator profile` (measured latency and power on the device), LeRobot policy-server backend, safety filter v0 (joint limits, workspace box, speed caps, watchdog hold), recorder that logs every decision and its outcome, run on a Jetson Orin Nano with an SO-101 arm |
| 0.2 | GPU scheduler that protects the control loop, speech (Whisper and an Indian-language ASR model), model profiles (for example 1 vs 10 denoising steps), warm-up and compile caches, C API and Python client |
| 0.3 | Safety filter on the servo bus, onboard, edge and cloud placement tested against real network drops, a published benchmark, and model data from the [Robot Model Index](https://github.com/armature-ai-labs/robot-model-index) |

## Repository layout

```
crates/commutator-router/   routing core (library): config, signals, decisions, ranking
crates/commutator-server/   the `commutator` binary: CLI and HTTP API
tests/parity/fixtures.json  solo-router's decisions for the parity grid
scripts/gen_parity_fixtures.py  regenerates the fixtures from a solo-router checkout
```

## Development

```bash
cargo fmt --all
cargo clippy --all-targets -- -D warnings
cargo test --workspace
```

To refresh the parity fixtures after changing the default config or the request grid:

```bash
python scripts/gen_parity_fixtures.py /path/to/solo-router   # needs pyyaml
cargo test -p commutator-router --test parity
```
